# Personal Task Progression Design

## Goal

让 bot 的想法、日常安排与社交事项以持久化任务为中心持续演进，而不是在相同念头上重复生成。

## Model

新增独立的个人任务存储。每个任务包含标题、来源、状态、下一步、优先级、创建与更新时间、关联用户/群、等待截止时间、上次推动时间、阻塞原因和最近进展。

状态为：`pending`、`in_progress`、`waiting_for_person`、`completed`、`snoozed`、`abandoned`。只有未完成状态会进入上下文；`snoozed` 在复查时间前不打扰。

## Creation

日/周/月计划生成后同步为任务。明确承诺、约定、待办和高行动潜力的内心独白可创建或增强任务。纯情绪和没有可执行下一步的感受不会创建任务。

相似的候选事项合并到已有任务，并写入新的进展；不会创建多个换词版本。

## Progression

对话后由模型基于结构化工具返回任务变更：创建、更新下一步、等待回复、完成、搁置或放弃。程序只接受已有任务 ID 的状态变更，未知 ID 不产生副作用。

活动完成会推进匹配的日常任务。定时检查会找出到复查时间的任务：等待他人超时后改为需要决定下一步；没有外部依赖的任务按优先级进入待推进状态。它不会凭空把任务标记完成。

内心独白读取任务的标题、最近进展和下一步。对同一任务可以再次思考，但必须表达状态变化、决定或等待，而不能重述旧文案。

## Proactive Messaging

主动消息只从任务的明确下一步产生。当任务处于 `waiting_for_person` 时，允许在复查时间后且未超过重试上限时发一条自然跟进；发送后更新时间和重试次数。收到关联用户消息后，任务退出等待状态并由对话分析决定下一步。

日常自驱任务可以通过活动系统启动或完成，但没有明确社交对象时不得借任务名义向群聊广播。

## Integration

任务上下文注入对话、主动消息和内心独白。现有日/周/月计划保留为用户可见的高层计划，任务系统承担执行态；完成任务时回写同名日计划项。

## Safety And Limits

任务数量受限；只保留近期完成任务作为历史。所有社交推进遵守现有群冷却、回复状态和消息去重机制。等待超时后的默认动作是搁置或决定是否重试，不是连续催促。

## Verification

测试覆盖：候选任务去重合并、合法状态迁移、关联回复解除等待、到期复查、重试上限、任务上下文与内心独白状态变化。集成检查包括 `cargo test` 和 `cargo check --lib`。
